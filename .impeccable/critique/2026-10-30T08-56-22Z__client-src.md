## Design Specificity Verdict

**LLM assessment:** Competent, consistent, and category-interchangeable. Every screen runs the same template (dash-prefixed eyebrow over H1, rounded card, icon-in-circle stat card, count pills); swap the copy and it is a habit tracker. "The Market Notebook" from DESIGN.md never shows up on screen. The genuinely product-specific parts are behavioural: money honesty (unknown is never zero, everywhere) and the Still to buy / Purchased split. The composition ignores the usage scene: couch planning (prices, budget, sort, refresh) and aisle shopping (one thumb, glance, tick) share one dense page.

**Deterministic scan:** `impeccable detect` over client/src + index.html returned 0 findings (exit 0) across 41 files, but regex-only: element rules (contrast, tiny text) could not run on JSX. A URL scan of production timed out, then hit HTTP 503. Clean here means "not measured", not "clean". Measured on the live sign-in page: all text pairs pass AA (lowest 5.60:1), focus rings are 3px green at 6.51:1 (mint 10.18:1 on the dark panel), inputs and buttons 50px. Detector-side catches the review missed: input borders are 1.33:1 against white (the border is the only field edge); the story-panel h2 precedes the h1 in the DOM; a 0×0 duplicate `.brand-home` button is focusable; the footer link is a 64×16 target. False positive from the browser pass: "dark mode not OS-driven" is wrong; `client/src/appearance.js:10` uses matchMedia.

**Visual overlays:** none. The site's CSP (`script-src 'self'`) blocked detect.js injection, so no overlay is visible in any tab. A real element-level run needs a local dev server or built `client/dist`.

## Overall Impression

The engineering of trust is excellent: money honesty, a frozen review snapshot, duplicate-safe finish, optimistic checks with rollback. The phone experience in the aisle, the one PRODUCT.md puts first, is where it falls down: chrome and planning controls push the checklist below the fold, every row carries edit/remove/price noise, and the best moment (finishing) ends in silence. Biggest opportunity: make the phone list screen a pure checklist.

## What's Working

- **Unknown is not zero, everywhere.** BigInt cents in money.js, "Not recorded" / "No prices entered", known-only totals with counted incomplete notes, a budget bar that returns nothing rather than lying, and aria-valuetext that says "known prices only, incomplete". Rare and fully product-grounded.
- **Finish review as a safety net.** Snapshot frozen during review, specific conflict copy, "it will not create a duplicate trip" retry, focus moved in, trapped and returned. Right care at the riskiest moment.
- **The check target.** A real checkbox inside a 44×44 label with a 26px round mark and focus-within ring; optimistic with rollback; done items move out of the way.

## Priority Issues

**[P1] The phone list screen buries the checklist and overloads every row**
- Why it matters: `.shopping-heading .catalog-button { width: 100% }` (styles.css:144) stacks My Lists / Refresh list / Add Item / Finish shopping full width; with heading, subtitle, progress card, sort toolbar and the site header the first row lands around y≈640 of 812 (estimated). Each row also carries Edit + red Remove on a second full-width line and an empty "Estimate: Not recorded · Actual: Not recorded" line (ShoppingList.jsx:332). Contradicts "checklist first, prices secondary".
- Fix: Row = circle, name, quantity; show price only when recorded; tap the row body for an edit sheet that holds Remove. Header = Add + overflow; drop My Lists (nav has it) and Refresh list; move Finish into the progress card.
- Suggested command: /impeccable distill, then /impeccable layout

**[P1] Adding from Catalog is a round trip per item; the promised quick add and list search don't exist**
- Why it matters: Each add navigates back to the list and auto-opens the editor with autofocus, popping the phone keyboard (App.jsx:330-331, ShoppingList.jsx:88-99). The Catalog "added" notice never renders because Catalog unmounts. PRODUCT.md promises quick add and list search on the list screen. A 20-item list = 20 bounces.
- Fix: Stay in Catalog after an add with an inline "Added ✓" state and a sticky "5 added to Weekly shop · Done" bar; open the editor only when re-adding an existing entry. Add a search / quick-add field to the list.
- Suggested command: /impeccable shape

**[P1] The Finish Trip ending is lost and completion is never celebrated**
- Why it matters: setFinished / setNotice run, then onBackToLists() navigates away (ShoppingList.jsx:144-146); My Lists shows nothing and the list silently vanishes. At 100% checked, Finish stays a secondary button at the top. Peak-end failure on the most important moment.
- Fix: Lift a flash message to App/Lists: "Weekly shop saved to Trips · View trip". When remainingCount is 0, promote Finish to primary inside the progress card or at the list end.
- Suggested command: /impeccable harden, then /impeccable delight

**[P1] No weekly reuse**
- Why it matters: Finishing consumes the list; there is no shop-again or duplicate-from-trip. PRODUCT.md calls it a "reusable grocery checklist" yet says future lists are created explicitly, so weekly shoppers rebuild through the per-item round trip above. Needs a product decision.
- Fix: "Start a new list from this trip" (all items, or not-bought only) on trip detail and the Lists card.
- Suggested command: /impeccable shape

**[P2] Keyboard / screen-reader gaps, sub-44px targets, tiny text**
- Why it matters: Checking moves the li to another <ul>, losing focus; focus isn't restored after closing the editor or removing; two aria-live regions announce every check (ShoppingList.jsx:362-363); the checkbox label flips with state. Targets under DESIGN.md's 44px floor: chips 32px, small buttons 36px, list-card actions and hide-purchased 40px. 10–11px text for categories, prices, quantity and mobile nav labels, read at arm's length. Input borders at 1.33:1.
- Fix: Focus the next unchecked checkbox after a check; static name-only checkbox label; one polite live region; 44px minimums; 12–13px floor; a stronger control-border on inputs.
- Suggested command: /impeccable harden, then /impeccable typeset
