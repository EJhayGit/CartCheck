# CartCheck implementation roadmap

**Status:** Proposed for review. Each milestone is independently demonstrable and has a focused gate. Do not begin implementation until this design is reviewed.

| Milestone | Functionality and important dependencies | Expected deliverables | Acceptance criteria | Required verification |
| --- | --- | --- | --- | --- |
| **1. Foundation and data rules** | Replace sightings schema with account, starter/product, shopping-trip, trip-item, and session tables. Establish currency/quantity/money rules and idempotent ~100-product starter seed. Depends on approved currency list. | Numbered migration(s), fresh schema, seed, domain validation/totals helpers, updated local setup. | Fresh disposable DB initializes twice without duplicate starters; no fabricated starter prices; zero and null remain distinct; `each` rejects decimals. | SQL migration/constraint checks plus `node:test` for money, quantity, and currency rules. |
| **2. Accounts and deployment shell** | Register, sign in/out, session restore, ownership middleware, server validation, rate limits, same-origin production serving. Depends on milestone 1. | Auth API, cookie sessions, React auth gate/forms, private starter copies and first active trip on registration, secure configuration and real-API build path. | Refresh preserves login; logout revokes it; unauthenticated private requests fail; second account sees no first-account data; production has no mock fallback. | API integration with two accounts, cookie/Origin checks, client build, production-mode local smoke check. |
| **3. Catalog and product detail** | Search/filter private starter copies and custom products, register custom product, edit private products, image fallback, labeled reference and last-paid sources. Depends on accounts and products schema. | Catalog/product APIs, catalog screens, product form/detail. | ~100 starter copies appear without current prices; one shopper's changes remain private; no-result search prefills registration; catalog edit cannot alter stored snapshots. | Repository/API isolation and validation tests; keyboard, empty/error, narrow-width manual checks. |
| **4. Active cart and budget** | Add/edit/remove one row per product; quantity/unit price/bought state; hide checked; budget and complete/incomplete totals. Depends on catalog and money rules. | Cart APIs, cart screen and summary, revision handling. | `each`, `kg`, `L` line totals round correctly; zero is known; unknown is flagged; duplicate add has one row; checked items can be hidden and unmarked; budget warning does not block editing. | Domain and API tests for totals/duplicates/revisions; responsive and keyboard walkthrough. |
| **5. Finish Trip and history** | Confirmation, transactionally archive checked and unchecked items, idempotent retry, fresh empty cart; list/detail of finished trips. Depends on cart and accounts. | Finish endpoint, trip summaries/detail, review UI. | Bought item needs a known price; unchecked item is recorded not bought; original currency and budget persist; duplicate confirm creates one trip; next cart starts empty with null budget. | DB/API concurrency and retry tests; complete browser trip; refresh and sign-in persistence check. |
| **6. Trip correction and price history** | Review/confirm add/remove/edit past items; derive corrected totals and last-paid prices. Depends on finished trips and product detail. | Trip correction endpoint/UI and dated per-product price history. | Original trip date and item snapshots remain visible; stale correction is rejected; changed bought status/price changes last-paid; currencies/units are not mixed. | Integration tests for correction, snapshot stability, stale revision, price-history ordering; UI confirmation/error walkthrough. |
| **7. Release verification and documentation** | Final responsive/accessibility pass, secure public deployment, operational checks. Depends on all features. | Public HTTPS client+API+PostgreSQL, updated README/env examples/Compose/workflow and course evidence. | Complete shopper cycle works publicly across sessions; another account remains isolated; phone portrait/landscape/desktop and light/dark states work; no secrets or real personal data ship. | Client build, all automated tests, disposable DB migration, manual accessibility and breakpoint matrix, `/healthz`/`/readyz`, dependency audit and security/privacy checklist. |

The milestones are sequential where data/API contracts require it. Within a milestone, UI and API work can be reviewed against its acceptance criteria without carrying unfinished behavior into the next milestone. The API and deployed database become the source of truth by milestone 2; mock fixtures remain only an optional local UI aid.
